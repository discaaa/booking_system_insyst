# BookaRoom
A room booking web application built with React and Vite.

## Features
- Browse available rooms
- Select booking dates and time slots
- Enter customer details
- Review booking information
- View booking confirmation

## Tech Stack
- React
- Vite
- CSS
- JSON Server (for mock API data)

## Booking Flow :
1. Choose a room - user can choose any room based on capacity, facilities, and price
2. Pick a date & time - user can choose available date and time slots
3. Entry user details - user is required to input their details to book a room
4. Review - user can review and recheck the room details and their profile details
5. Confirmation - the system sends a booking request to API
6. Success - the system display a booking summary and code from API response

## Execute the Program :
1. Clone the repository 
git clone https://github.com/discaaa/booking_system_insyst.git

2. Install the dependency
npm install

3. Run mock API
npx json-server@0.17.4 --watch db.json --port 3001
(API runs at : http://localhost:3001)

4. Run FrontEnd
npm run dev
(FrontEnd runs at : http://localhost:5173)

## Data Structure
The db.json file uses three main collections:
1. rooms - Stores room information:
id: Room ID.
name: Room name.
capacity: Maximum participant capacity.
pricePerHour: Rental price per hour.
facilities: List of facilities.
image: URL of the room image.

2. slots - Stores time slot information:
id: Slot ID.
roomId: ID of the room to which the slot belongs.
time: Booking time range.
isAvailable: Initial availability status of the slot.

3. bookings - Stores booking data:
id: Booking ID generated by the API.
roomId: ID of the booked room.
slotId: ID of the selected time slot.
date: Booking date in YYYY-MM-DD format.
name: Name of the person making the booking.
email: Email of the person making the booking.
phone: Phone number of the person making the booking.
participants: Number of participants.
purpose: Purpose of the booking.
notes: Additional notes.

## Validation and Error Handling
The frontend implements the following validations:

1. Name, email, phone number, and booking purpose are mandatory fields.
2. The email must follow a valid email format.
3. The phone number must consist of 10–15 digits, excluding separators such as spaces, parentheses, plus signs, and hyphens.
4. The number of participants must be at least one and cannot exceed the room's capacity.
5. The room, date, and time slot must be selected before proceeding to the next step.
6. Slots that are unavailable or already booked for the same room and date cannot be selected.
7. A loading indicator when fetching room and slot data.
8. Error messages if an API request fails.
9. A loading indicator when submitting a booking.
10. Error messages if the booking submission process fails.

## Use of AI
AI is used as an assistive tool during the development process, not as a substitute for understanding or testing the code.

The use of AI includes:
1. Assisting in understanding the multi-step booking flow using React and state management with Hooks.
2. Helping to review data-fetching logic via the Fetch API, as well as the handling of loading states and errors.
3. Assisting in analyzing slot availability issues when multiple bookings occur for the same room on the same date.
4. Helping to review user input validation and the booking confirmation flow.

### Code generated or suggested by AI is reviewed, adapted to the project structure, and tested using a mock API. AI is employed to support the learning process, debugging, and the evaluation of the implementation.
